# Python 基线迁移到 TypeScript 的结果

本页记录的是接入神经网络之前的规则基线迁移结果。后续 GRU/MLP 推理接入及其独立验证见 [MODELS.md](MODELS.md)；本页历史跑分和耗时不能作为接入模型之后的整场成绩。

日期：2026-10-05。结论：可以在这个独立 TS 项目上继续开发。当前基线的主要规则、20 个默认参数、曝光账本和反馈解释均已迁入；本次自生成数据上的得分保持接近，智能体处理请求的 CPU 用时明显下降。

## 迁移范围和来源

- 来源为 `agents/claude-baseline-v1/agent`。六个核心模块的内容与 `2b5ae76` 的 v1.0 一致；入口包含后来新增的完整输入日志。源码散列和本次固定的提交见 `SOURCE_MANIFEST.json`。
- 七个 Python 运行文件分别迁入 `src/agent.ts` 和 `src/core/`。新增 `compat.ts` 处理取余、整除、浮点求和、中位数和排序顺序。
- 保留指向、分配目标、曝光时长、天气/仪器判断、地形学习、请求截止约束、均匀度、季节紧迫度、指向偏差与账本撤销。未调整策略参数，未新增模型决策或额外时间/长度截断。
- 项目使用 Node.js 22；运行不需要 Python 或第三方运行依赖。Python 仅用于本地引擎及对照工具。npm 依赖仅用于构建。
- 原 Python 项目在对照过程中有其他工作更新输入日志。迁移没有修改或覆盖它；对照工具固定使用 `results/python-source-snapshot` 中与来源散列相符的代码，避免混入后续变化。

## 输入和比较方式

输入为 `evaluation_assets/formal-v4-feedback-self-generated-v3/nominal/cards/a` 至 `d`：正式公开目标、配置和日历，加自行生成的天气、事件与请求。A/B/C/D 的生成种子分别为 8105001、8105002、8105003、8105004。

每张卡的 7 个公开文件均与 `cards/a` 至 `cards/d` 及生成记录中的 SHA-256 相同，共核对 28 个文件。天气、事件和请求另存于自生成数据目录。这些数据不代表比赛隐藏数据；本次没有读取、下载、恢复官方练习卡，也没有上传或提交线上比赛。

完整运行使用仓库内官方本地引擎。两版独立做决定，使用原有 CPU/经过时间预算调整规则，保留完整输入日志；每张卡的 CPU 预算为 900 秒、经过时间上限为 1800 秒。没有为迁移额外增加超时兜底。

运行环境为同一台 macOS arm64 机器，Python 3.12 与 Node.js v22.23.3。部分完整运行与同输入对照同时进行，系统负载和引擎的机器校准值不同；下列时间是本次实际观测，不是严格控制负载后的多次测速平均值。

## 同输入的状态更新检查

独立对照工具将两版搜索范围固定为 14。引擎按 Python 动作返回反馈，TS 使用相同的曝光记录解释反馈。比较最近曝光涉及的目标得分与完成条件、剩余必做目标数、各区域完成数、请求奖励和截止时间、天气/仪器状态、故障报告计数、指向偏差及不确定范围。

数字比较容许绝对误差 `1e-8` 或相对误差 `1e-10`；布尔值、结构和动作字段另外比较。**这证明了所检查字段在同一份反馈下相符，不证明两版会在独立运行中走完全相同的路线，也不是 TS 的独立得分。**

严格逐步对照的第一次分歧发生于 A 第 268、B 第 150、C 第 223、D 第 90 次决定。已保存现场到 `results/parity-debug-v3/`。其中 D 的两个候选价值分别为 `46.64544336921078` 与 `46.64544336921076`，差约 `2e-14`；两种语言的小数末尾差异会改变候选起点，进一步改变网格细调和曝光选择。A 的某次细调也出现接近并列的网格位置。没有改写原策略的并列处理规则来强行消除这些差异。

同反馈检查在 `results/feedback-nominal-v3/summary.json`，全部数字为实际比较结果。严格对照中途结束的分数不能当作完整跑分使用。

## 构建、包和输入输出

- 在 Node.js 22 下 `npm ci --include=dev`、`npm run build`、`npm run pack` 成功。
- 从 ZIP 解压到新的空目录，重新安装锁定依赖并编译，随后以纯 Node.js 程序运行成功。ZIP 根目录含 `observer.project.json`。
- 核对标准输出只含正确的比赛回复，标准错误保留原文日志；覆盖空行、错误 JSON、240011 字节的中文输入行、CRLF，以及末尾没有换行的输入。收到 7 行，产生 3 条有效决策回复，日志原文逐行相符。
- ZIP 不含 Python、评测数据、结果、密钥文件、依赖安装目录或已编译目录；解压后的源码重新构建。包的确切大小、文件数和散列见 `results/package-check.json`。
- 构建清单把 npm 缓存放在 `/workspace/.npm-cache`；运行不写根目录。已经检查本地包大小限制。Docker 后台服务没有运行，因此 **Linux x86_64、2 核/2 GB、只读根目录的实际容器运行尚未验证**；本地成功不能替代这项验证。

## 后续使用

现阶段建议继续使用这个 TS 项目作为开发基线，保留 Python 快照作为比较依据。已有得分和耗时证据支持迁移；后续调整策略或增加模型环节，应再用同一组允许的数据比较。

当前仍为纯规则对照版，没有接入正式作品要求的模型环节。本报告只确认迁移和本地结果，不表示正式参赛作品已经完成或预测隐藏卡分数。
